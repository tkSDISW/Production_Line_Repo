## Comparing SEMI E10/E58 vs. PackML as a basis for the machine fault-recovery state model

**Context:** evaluating candidate standards to base the Capella state-machine model on for equipment states, specifically the "fault → recovery sequence → back online" behavior.

### SEMI E10 — accounting standard, not a control standard
Six top-level time buckets, hierarchical:
```
Total Time
├── Non-Scheduled Time
└── Operations Time
    ├── Downtime
    │   ├── Scheduled Downtime
    │   └── Unscheduled Downtime
    └── Uptime
        ├── Engineering
        ├── Standby
        └── Productive
```
Defines RAM math (MTBF, MTBI, MTBA, MCBF, MCBI, MCBA) — the basis for OEE/RAM reporting. **Explicitly does not define transitions between states** — no events/triggers, nothing directly implementable in a control system.

### SEMI E58 (ARAMS) — fills the transition gap, for automated equipment
Converts the E10 stack chart into an actual state diagram with defined transition triggers, and adds sub-states describing *why* a bucket applies (e.g. `Machine Failure`, `Wait Exception`, `Maintenance`, `Waiting for Setup`, `Change Lot/Setup`, `Standby for Operator`, `Standby for Material`, `Engineering for Sale`).

Fault scenario in E58 terms: Productive → (fault) → Unscheduled Downtime [Machine Failure] → Unscheduled Downtime [Maintenance] → (repair verified) → Standby [Standby for Operator] → Productive. Coarse — the whole recovery collapses into one bucket ("Unscheduled Downtime") tagged with a reason.

### PackML (ANSI/ISA-TR88.00.02)
17-state control-level model, explicitly separating stable "Wait" states from transient "Acting" states, with named commands driving each transition (Reset, Start, Stop, Hold, Unhold, Suspend, Unsuspend, Abort, Clear). The fault-recovery sequence is modeled explicitly and granularly: `Execute → (fault) → Aborting → Aborted → (Clear cmd) → Clearing → Idle → (Reset cmd, if needed) → Resetting → Idle → (Start cmd) → Starting → Execute`. Also separately models operator-initiated pause (`Held`/`Un-Holding`) vs. line/external-condition pause (`Suspended`/`Un-Suspending`), each recovering via its own path rather than a full fault/abort cycle.

### Conclusion / recommendation
- E10/E58 = reporting vocabulary (why time was lost, rolled up for OEE/availability metrics).
- PackML = actual control-level behavior (how the machine steps back online).
- Not mutually exclusive: PackML can drive the state machine in the Capella model; E10/E58 categories can be used to tag/roll up PackML states for availability reporting on top.
- **Leaning toward PackML as the basis for the Capella state machine itself**, given the stated purpose of this repo is to capture how machines change and recover through states — not primarily an OEE reporting need. Not yet a final decision.
