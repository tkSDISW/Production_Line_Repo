## Filling Station exchange item allocation complete; YAML allocation confirmed supported

**Status:** Active

All 9 of Filling Station's exchange items are now allocated onto their correct functional exchanges (capella-fabric commit 020fec16, pushed to master), mirroring Infeed Load's pattern exactly:

- `FillingStation.OperatorControl`: stop, start, hold, unhold, reset, clear
- `FillingStation.LineControl`: suspend, unsuspend
- `FillingStation.MachineStatus`: abort, machineStateComplete

Confirmed both correctly and via the component-exchange roll-up (`FillingStation.OperatorInterface`, `FillingStation.LineControlInterface`).

**Capability confirmed:** exchange item allocation onto a FunctionalExchange IS supported via capella-fabric's `apply_model_patch`, using `extend: exchange_items: [!uuid ...]` on the target FunctionalExchange. This answers the earlier open question (raised when starting on Filling Station) about whether allocation is possible through the YAML patch interface rather than requiring manual work in Capella — it is, and it can be used for the remaining 2 stations (Capping, Labeling/Inspection, Case Packing) once their exchanges exist.

Also caught and the user fixed along the way: a stray orphan component port (`CP 3`) created instead of reusing Filling Station's existing pre-named `Line Control I/F` port, and a mis-allocated `FillingStation.machineStateComplete` sitting on the wrong (Infeed Load's) `Machine Status` exchange. Both resolved before this allocation pass.
