## Scene 5 dry run: "Filling Station is reporting Aborted. What do I do?" read against the model

**Status:** Active

A dry run of the Scene 5 question (NOTE-0010), done by reading the model (capella-fabric, master, commit e2074b0) and answering from it. This is not the Simcenter agent's actual output, only what the model supports.

### What the model supports (checked in the model)
- **How Filling gets to Aborted:** only from Execute, via the `abort` transition (trigger `FillingStation.abort`). The transition description notes TR88 allows abort from most states, but this model wires it only from Execute.
- **The only way out:** one outgoing transition from Aborted, `clear` (trigger `FillingStation.clear`), to Idle. Idle then needs `start` to return to Execute. `reset` is not part of this recovery. It applies only from Complete or Stopped.
- **Who can issue clear:** `FillingStation.clear` is allocated only on the Operator exchange (`FillingStation.OperatorInterface` and `FillingStation.OperatorControl`, Control Machine to Manage States). Line Control's exchanges carry only suspend, unsuspend, abort and machineStateComplete. This holds for all five stations. The script claim "only the Operator can issue clear" is correct.
- **What Filling reports:** `FillingStation.abort` goes out on Machine Status to Line Control's Control Machines.
- **Recommended answer:** diagnose and correct the fault (Aborted description: recovery requires diagnosis or repair before clear), Operator issues clear (Aborted to Idle), Operator issues start (Idle to Execute).

### Findings that affect the script
1. **"Downstream" does not match its stated reason.** The `Control Machines` description (DEC-0015, reconstructed from NOTE-0007) says Line Control suspends the *downstream* machines "so in-flight material does not back up into a station that can no longer accept it". If Filling aborts, material backs up from the *upstream* side (Infeed Load keeps delivering into a station that cannot accept it). Downstream stations (Capping, Labeling, Case Packing) are *starved*, not backed up. NOTE-0007 carried the same wording, and DEC-0015 reproduced it. Scene 5 repeats "downstream". Which machines are actually suspended is not a modeled fact, so the wording is a decision for Tony.
2. **The unsuspend trigger is not modeled.** The script and the `Control Machines` description say Line Control unsuspends machines once Filling recovers. Machine Status carries only `abort` and `machineStateComplete`. Nothing reports "returned to Idle", so the model gives Line Control no signal that recovery happened.
3. **No live state in the model.** The agent cannot know the cause of the abort or which stations are currently suspended. It can only say what the model requires.

### Next
Decide the wording: for example, "suspends the other stations" or "upstream blocked, downstream starved". Then update `Control Machines` and the Scene 5 narration together. Not changed yet.
