## History of the PackML standard

**Purpose:** background context for why PackML (see NOTE-0002) was chosen as the basis for the fault-recovery state machine.

### Timeline

- **Late 1980s** — ISA begins developing a set of batch-control standards (ISA-88), aimed at improving system performance and programming efficiency via standard models and procedures. A later part (Make2Pack) targets Equipment Modules and Control Modules specifically.
- **Early 2000s** — OMAC (Organization for Machine Automation and Control) starts developing a parallel standard aimed at packaging machines, borrowing ISA-88's underlying concepts but built for discrete machine control rather than batch chemical/pharma processes.
- **2005** — OMAC affiliates with ISA, setting up the later formal merger of the two efforts.
- **2008** — ISA publishes ANSI/ISA-TR88.00.02-2008, "Machine and Unit States: An Implementation Example of ISA-88," harmonizing the two parallel efforts. This becomes the formal basis for PackML. OMAC also develops **PackTags** alongside the state model — a standardized data-tag vocabulary enabling PackML machines to communicate with each other and with MES/SCADA systems.
- **v1/v2/v3** — the OMAC guideline goes through several iterations; PackTags are eventually folded directly into the guideline documents.
- **2009** — Procter & Gamble publishes a PackML Implementation Guide to help developers implement it cleanly. Major automation vendors (e.g. Rockwell Automation) build native support for the ISA-88 modularity/PackML concepts into their programming environments.
- **2015** — Standard revised as ANSI/ISA-TR88.00.02-2015, developed by the OMAC Packaging Workgroup, specifying unit state models and operation modes for machine control and packaging line implementation. This is the generally-referenced current version, and the source for the 17-state model recorded in NOTE-0002.

### Takeaway

PackML is not a from-scratch invention — it's a purpose-built adaptation of ISA-88 batch-control state modeling for discrete packaging/machine control, matured over 15+ years with real end-user (P&G) and vendor (Rockwell, others) input, which is a large part of why it's held up as a de facto industry standard.
