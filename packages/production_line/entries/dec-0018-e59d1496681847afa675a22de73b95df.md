## Held-exit status item added (resumedExecute, 5 machines) and Scene 5 narration updated

**Status:** Active. Follows DEC-0017 and closes its gap 1.

Tony Komar approved adding the Held-exit notification and updating the Scene 5 narration.

### Model change (capella-fabric, pushed to master)
- **Commit 6418c410:** created 5 ExchangeItems in the LA `Data` package, one per machine, named `<Machine>.resumedExecute` per DEC-0007: InfeedLoad, FillingStation, CappingStation, LabelingStation, CasePackingStation. Each description says the machine has left Held and returned to Execute after unhold, that it is not a TR88 signal, and why it was added.
- **Commit 2abacead:** allocated each item onto that machine's Machine Status functional exchange (`Machine Status` for Infeed Load, `<Station>.MachineStatus` for the others), using the technique in NOTE-0009.
- **Checked:** `verify_model` on LA reported no issues. Reading the model back showed each of the five exchanges now carries six items: abort, machineStateComplete, stopped, held, returnedToIdle, resumedExecute.

With DEC-0017, every way out of Stopped, Aborted and Held now has a modeled notification to Line Control: `returnedToIdle` for Stopped (after reset) and Aborted (after clear), `resumedExecute` for Held (after unhold). Line Control's unsuspend condition ("no machine Stopped, Aborted or Held", DEC-0016) can now be evaluated from modeled inputs.

### Narration change (NOTE-0010, Scene 5)
The last sentence now reads: "It also notes that Filling Station reports the abort to Line Control, which suspends the rest of the line, and unsuspends it once Filling Station reports that it is back in Idle." It replaces the "downstream of the fault" wording found wrong in OBS-0007. The replacement was drafted from the model, not dictated. Pre-recording checks were added to NOTE-0010 (model versus live behavior, suspend only from Execute, refresh Capella).

### Still true (not changed)
1. **`resumedExecute` is a model addition, not a TR88 signal.** The name is my choice, in the camelCase style of the other items. Rename it if you want something else.
2. **Nothing emits these items.** No state or transition in any state machine references any of the four status items. They are allocated on the exchanges only.
3. **Suspend only works from Execute.** In every station's state machine the `suspend` transition runs only from Execute. A machine in Idle, Stopped or Complete has no suspend transition.
4. **`Control Machines` description unchanged.** It still describes the logic in prose and does not name the status items.
5. **Component-exchange roll-up not read back.** Infeed Load's Line Control component exchange runs the opposite direction from the other four stations.
