## Model check on resuming the project, and Infeed Load exchange names normalized

**Status:** Active

Resumed work in November after a gap since September. Connected to the Capella model (Production_Line_Equipment_Model, master) at the user's latest commit 406e3af and checked it before changing anything.

### Check results
- `File Bottle` (Filling Station function, flagged earlier as a likely typo) was already corrected to `Fill Bottle` by the user. No change needed.
- Logical-layer quality scan (`verify_model`, LA): no empty names, no unallocated functions.
- No auto-generated names remain on component exchanges or on functional exchanges.

### Change made
Two Infeed Load component exchanges had been given an `InfeedLoad.` prefix but kept spaces, unlike every other station. Normalized to the no-space convention used elsewhere (capella-fabric commit 3d4b44b1, pushed to master):
- `InfeedLoad.Line Control Interface` -> `InfeedLoad.LineControlInterface`
- `InfeedLoad.Operator Interface` -> `InfeedLoad.OperatorInterface`

This brings all five stations' control-plane component exchanges into the same `<Station>.<Role>Interface` pattern (NOTE-0005, DEC-0007).

### Reminder for next time
The user's local Capella copy must be refreshed from the remote before editing, since this change landed on master from outside Capella. An unrefreshed local push is what overwrote earlier work in September (see DEC-0009 and the diverged-push recovery).
