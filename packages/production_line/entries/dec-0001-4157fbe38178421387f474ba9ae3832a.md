## Decision: demo line design — 5-station bottling/packaging line, built via REC/RPL

**Status:** Active

### The line

1. **Infeed / Load Station** — receives empty bottles from upstream, positions them onto the line conveyor
2. **Filling Station** — meters and fills product into each bottle
3. **Capping Station** — places and torques the cap
4. **Labeling & Inspection Station** — applies label, then vision-checks fill level/cap/label presence
5. **Case Packing / Outfeed Station** — groups bottles and packs them into cases for outfeed

Chosen for demo purposes: intuitive to explain, each station has an obvious discrete cycle (one bottle/case = one PackML `Execute`) and an obvious fault mode (jam, sensor miss, out-of-material) mapping cleanly to `Abort`/`Clear`. Stations are all structurally "the same kind of thing" — material in, one operation, material out — which is what makes the REC/RPL build approach worth demonstrating.

### Build plan

1. **Build the master Station** — one generic component with the PackML state machine (NOTE-0002) and standard ports: Material In, Material Out, Control/Command interface, Fault/Status signal. Built manually in the Capella desktop editor (see OBS-0002 — no agent-side support yet for creating state machines).
2. **Turn it into a REC** (Replicable Element Collection) — structure, ports, and state machine become the reusable template.
3. **Create 4 RPLs from it** — one each for Filling, Capping, Labeling/Inspection, Case Packing. All five stations start identical.
4. **Break the REC/RPL link** on the four replicas (and the original, if it also diverges) so each becomes an independent copy.
5. **Customize each station** — fill logic, cap torque logic, label/vision logic, case-pack logic — keeping the PackML state machine backbone intact on all five.
6. **Wire the line together** — Material Out → Material In in sequence (Infeed → Fill → Cap → Label/Inspect → Pack), plus line-level upstream/downstream conditions driving each station's Suspend/Unsuspend (PackML's external-condition pause path).

**Open question, not yet decided:** whether the Infeed station gets the full station shell (Material In/Out + state machine) for consistency, or a simpler treatment, since it also has a real fault mode (jam at infeed).
