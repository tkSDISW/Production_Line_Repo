## AI-assisted modeling session: from a cold start to a verified, demo-ready model in one sitting

**Status:** Active

Tony Komar called this session "an amazing demonstration of the power of AI-assisted modeling" and asked for it to be captured. This entry records what happened, what made it work, and what it does not show. The judgment of how impressive it was is Tony's. The rest is a factual account from the session.

### What happened (2026-11-22 evening to 2026-11-23 morning)
Starting point: a project resumed after about two months, a model and notebook the agent had not seen in that session, and a demo recording planned for the next day (NOTE-0010).

1. **Picked up the project from the notebook.** The agent read the purpose entry, the prior decisions and the video script, and found no behavior config. It drafted one from the repo's own history and the owner's direction (BCFG-0001).
2. **Audited the model.** A description check across the logical layer found that states, transitions and exchange items were well described, and that components, actors and functions were not. It also found one wrong description: `Control Machines` held the text of a transition, replacing the fault-isolation text recorded in NOTE-0007. How that happened is unknown.
3. **Proposed, then applied.** Descriptions for the missing elements were proposed for review, approved, and applied in one patch (29 elements, commit fd379ab4; DEC-0015).
4. **Dry-ran the demo against the model.** Reading the model to answer the Scene 5 question found that the model supported the claim "only the Operator can issue clear", and also found a contradiction in the Line Control wording: "suspends downstream machines so material does not back up" is backwards for a Filling abort (OBS-0007).
5. **Fixed the logic, then the structure.** On Tony's direction the line-suspend logic was written into `Control Machines` (DEC-0016). That exposed that Line Control had no modeled way to see Stopped or Held, so 20 exchange items were created and allocated onto the five Machine Status exchanges (DEC-0017, DEC-0018; commits 51e499b8, e57022ca, 6418c410, 2abacead).
6. **Kept the script in step with the model.** NOTE-0010 was revised in place five times (Scenes 1, 2, 4 and 5, then pre-recording fixes), with every change and every agent-drafted sentence marked in its revision notes.
7. **Final check before recording.** A last read against the model found three more script errors (a misspelled component, a missing function in the chain, an ambiguous phrase), resolved against the model and fixed.

Notebook entries produced along the way: BCFG-0001, DEC-0015 to DEC-0018, OBS-0007, and this one. Model commits were pushed to master as they were made.

### Why it worked
- **The notebook was the memory.** After a gap of two months the agent resumed from the recorded purpose, naming decisions (DEC-0007), the allocation technique (NOTE-0009) and the earlier diagnoses, instead of rediscovering them.
- **Read and write on the same model.** The agent could read the model's actual structure, patch it, and read it back, so claims were checked against the model, not remembered.
- **Verification after every change.** `verify_model` after each patch, and read-backs of the changed elements.
- **The human made the calls.** Every model change was proposed or confirmed by Tony first: which descriptions, the suspend logic, the status items, the Held-exit item. The agent supplied options, drafts and checks.
- **Everything was logged as it happened,** including the agent's own mistakes, so the record explains the model.

### What this does not show (read before citing it)
- **No measurement.** There is no timing and no baseline comparison. "Amazing" is Tony's assessment.
- **The agent made errors.** The "downstream" wording was reproduced from an earlier note into DEC-0015 without catching the contradiction. DEC-0015 also miscounted its own patch (28 stated, 29 applied; corrected by addendum). Both were caught by later checks in the same session, not by the first pass.
- **The model has real gaps.** No state or transition emits the new status items. `suspend` only works from Execute. The Infeed Load exchange direction and naming still differ from the other four stations (DEC-0014, DEC-0017).
- **Not yet validated with the Simcenter agent.** The Scene 5 dry run was the agent reading the model, not the demo agent's actual output.
- **Some checks were partial.** Descriptions were read back selectively, not all 29, and the diagrams were not opened.

### Why it is worth keeping
It is a worked example of the loop the demo is about: an engineer directing, an agent that can read and edit the model and the record together, and checks that catch the agent's own mistakes. Scene 4 of NOTE-0010 points the audience at the notebook as the evidence.
