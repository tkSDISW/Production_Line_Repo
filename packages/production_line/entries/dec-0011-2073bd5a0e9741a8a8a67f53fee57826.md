## Decision: separate repo for the simulator project

**Status:** Active

User is starting a new, separate deliverable: a production-line simulator, built with Claude Code, that:
- Captures its own requirements (including a set of UI requirements)
- Is implemented based on the Capella model (Production_Line_Equipment_Model)
- Uses a routine that pulls parameters from the model to update aspects of the simulation

**Options considered:**
1. Create a new GitHub repo (e.g. `Production_Line_Simulator`), registered/scoped to this agent, as its own notebook
2. Reuse this repo (Production Line Repo) with a new `simulator` package alongside `production_line`

**Decision:** Option 1 — a separate repo. Rationale: this is a genuinely separate deliverable (a Claude Code implementation project with its own requirements and UI spec, plus a model-sync routine) rather than more modeling notes on the existing line/state-machine work, and it will be handed off to Claude Code as its own project, so a dedicated repo fits better than a package within this one.

**Next step:** user will create the GitHub repo and register/scope it to this agent via the Cartenza settings page. Once done, Cartenza will connect (clone_knowledge_repo, resuming if already GitHub-authorized) and set it up starting with a `purpose` entry.

**Reference:** DEC-0010 (current production-line model state), this repo's own `purpose` entry (for contrast — this repo stays scoped to the physical line/Capella model, not the simulator).
