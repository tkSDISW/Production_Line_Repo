## PackML (ANSI/ISA-TR88.00.02) state model — reference for the machine fault-recovery state machine

**Purpose:** candidate basis for the Capella state machine modeling how a machine changes state on fault and progresses back online (see OBS-0001 for why this was chosen over SEMI E10/E58).

### The 17 states

**Wait states (stable — machine can sit here indefinitely):**
- `Stopped` — halted, the "off" starting point
- `Idle` — reset and clean, waiting for Start
- `Execute` — running production (also acts, since it's doing work)
- `Held` — paused by an internal condition (e.g. low material, minor fault needing operator service)
- `Suspended` — paused by an external/line condition (blocked or starved)
- `Complete` — batch/cycle finished
- `Aborted` — faulted; the machine had a problem

**Acting states (transient — moving between two Wait states):**
- `Resetting` (Stopped/Complete → Idle), `Starting` (Idle → Execute), `Completing` (Execute → Complete)
- `Holding` (Execute → Held), `Unholding` (Held → Execute)
- `Suspending` (Execute → Suspended), `Unsuspending` (Suspended → Execute)
- `Aborting` (any state → Aborted), `Clearing` (Aborted → Idle), `Stopping` (most states → Stopped)

### Commands driving transitions

| Command | Effect | Valid from |
|---|---|---|
| Reset | → Resetting → Idle | Stopped, Complete |
| Start | → Starting → Execute | Idle |
| Hold | → Holding → Held | Execute |
| Unhold | → Unholding → Execute | Held |
| Suspend | → Suspending → Suspended | Execute |
| Unsuspend | → Unsuspending → Execute | Suspended |
| Stop | → Stopping → Stopped | almost any state |
| Abort | → Aborting → Aborted | any state except Aborted/Aborting |
| Clear | → Clearing → Idle | Aborted only |

### The fault-recovery sequence (what this repo cares about)

`Execute → (fault) → Aborting → Aborted → (Clear cmd) → Clearing → Idle → (Reset cmd, if needed) → Resetting → Idle → (Start cmd) → Starting → Execute`

The machine cannot leave `Aborted` except via an explicit `Clear` — deliberate, so it never restarts with a fault unaddressed. `Held`/`Unholding` and `Suspended`/`Unsuspending` are separate, lighter-weight pause paths (internal vs. external condition) that do not go through the full abort cycle.

### Mapping into Capella

- One Capella State Machine on the Logical/Physical Component for the machine; states = PackML states, transitions labeled with the command name.
- Not all 17 states need to be implemented — many real systems trim to 8–10. Given this repo's focus on fault recovery, keep the full `Execute → Aborting → Aborted → Clearing → Idle → Resetting → Idle → Starting → Execute` chain intact even if other states are trimmed.
- Model the fault signal that triggers `Abort` as a Functional Exchange feeding a transition guard, rather than burying detection logic in the diagram.
- If OEE/availability reporting is wanted later, tag each PackML state with its SEMI E10 bucket (e.g. `Aborted`/`Aborting`/`Clearing` → Unscheduled Downtime) as a separate mapping table, not part of the state machine itself.

**Reference:** OBS-0001 (comparison against SEMI E10/E58).
