## Image specification: model-aligned logical architecture view

### Objective
The image is an **introduction to the Production Line model**. It is not a sales image and should not imply that a new product or tool is being sold. The customer already uses **Capella to design its product**. The intended thought to introduce is that the same model can also provide useful engineering context for **support, operation, fault understanding, and recovery**—an application they have not emphasized previously.

The desired audience reaction is: **“This is the model we are about to look at.”**

### Governing rule
**Model first, image second.** The Capella model is the authority. Use exact model names so the same subset can be placed on a Capella diagram and the presentation graphic remains visibly traceable to the engineering model.

### Image content and composition
The introductory image should primarily show **components + actor**, not all functions or exchanges.

Use recognizable industrial equipment/stations arranged as a production line, similar to the original generated image. Label each with its **exact Capella model name**.

Let the physical-looking stations dominate rather than drawing a heavy Capella-style system box. Communicate the Production Line context with a **subtle enclosure, common floor/platform, or restrained visual grouping**.

Place **Operator** clearly outside the Production Line context.

Place **Line Control** visually above or otherwise distinct from the station sequence so it reads as the element coordinating the machines rather than as another processing station.

Use **material transformation as the visual story** with minimal explanatory text: Bottle Pallet → empty bottles → filled/capped/labeled bottles → cases → Case Receiver. This should make the production process understandable before the audience studies the model itself.

Connections may provide visual structure, but detailed exchange/interface labels are not required on this introductory image.

### Deliberately deferred
Do **not** show PackML states, detailed functions, detailed interfaces, fault-recovery logic, MES, enterprise systems, generic PLC/controller layers, utilities, support services, or additional actors on this opening image.

Those concepts belong in the subsequent engineering story:
1. Introductory image — **what the system is**
2. Capella logical architecture — **how it is modeled**
3. State/fault-recovery content — **how the model becomes useful for support and recovery**

### Visual direction
Use the original production-line image as the aesthetic reference: recognizable, realistic industrial stations, clean landscape composition, minimal text, and enough systems-engineering structure to make the architecture understandable. Avoid a dense infographic and avoid a sales/marketing aesthetic.

### Model cleanup associated with this specification
Two naming issues exposed by using the model as presentation source content were corrected in the Logical Architecture:
- **File Bottle → Fill Bottle**
- **Bottle Pallette → Bottle Pallet**

This reinforces a useful side effect of model-derived communication: presentation use can expose small model-quality issues that are otherwise easy to overlook.
