## Allocating Exchange Items onto Functional Exchanges via `apply_model_patch`

**Purpose:** confirmed capella-fabric technique, drafted to hand off to Claude Code for addition to the Member Handbook's `mcp_tools` package.

**Confirmed working:** `apply_model_patch` can allocate one or more `ExchangeItem` objects onto an existing `FunctionalExchange`, using `extend` rather than `set`. This is a property extension on an existing object, not a creation of a new exchange — so it's within the tool's supported scope.

**Syntax:**
```yaml
- parent: !uuid <FunctionalExchange-uuid>
  extend:
    exchange_items:
      - !uuid <ExchangeItem-uuid-1>
      - !uuid <ExchangeItem-uuid-2>
```

Multiple items can be allocated in one call by listing multiple UUIDs; multiple functional exchanges can be patched in the same YAML by adding more top-level entries.

**Confirmed side effect:** the allocation correctly rolls up to the owning `ComponentExchange` automatically — no separate step is needed to reflect it at the component level. Verified via `generate_fabric` immediately after the patch, both at the functional-exchange level and the component-exchange level.

**Not supported — creating new exchanges:** this technique only works on a `FunctionalExchange` that already exists. `apply_model_patch` does not support creating new `FunctionalExchange`, `ComponentExchange`, or `PhysicalLink` objects — only functions, ports, and structural components can be created via `extend`. If the functional exchange doesn't exist yet, it has to be created manually in Capella first; once it exists, item allocation onto it can be done via this pattern.

**Worked example from a real session:** allocating a `stop` command's exchange item onto a station's `OperatorControl` functional exchange:
```yaml
- parent: !uuid b575dc55-891b-43ea-8809-91ff4a628138
  extend:
    exchange_items:
      - !uuid d46776cf-56b9-49d7-9d21-6231988436ba
```
This confirmed both the allocation itself and its correct roll-up to the parent component exchange, which had been previously named to reflect the wiring (e.g. `FillingStation.OperatorInterface`).
