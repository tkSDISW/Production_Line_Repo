## Video script: Production line model, engineering notebook, and AI-assisted recovery

**Purpose:** narration script for a ~4-5 minute video, written to be read directly from this entry while recording. Narration is in quotes; the "On screen" lines say what to have visible.

### Scene 1: The system at a glance (~30s)
**On screen:** explicitly load and display `[LAB] Production Line (Components Images)`. Show the material path from Bottle Pallette through the five stations to Case Receiver, with Operator and Line Control off to the side.

> "This is a five-station bottling line modeled in System Modeling Workbench based on Capella: infeed, filling, capping, labeling and inspection, and case packing. Material flows left to right. Two control actors, the Operator and Line Control, sit above the line and drive every station."

### Scene 2: Inside the machines (~60s)
**On screen:** explicitly load and display the diagram `[LAB] Control Filling Control`. Zoom into one station. Show its `Manage States` function and its three exchanges (Operator Control, Line Control, Machine Status). Then show the material function chain: Supply Bottle, Load, Fill, Cap, Label, Inspect, Case Pack, Receive Case.

> "Each machine has the same control shell. Commands come in from the Operator and from Line Control, and status goes back out. Behind that is the function chain that follows the bottle through the line. In this example you can see the Control Filling Station Functional flowing through the Operator, Filling Station and the Line Control."

### Scene 3: One machine's state machine (~45s)
**On screen:** the `[MSM] TR88 PackML 7 state` diagram. Hover on Aborted, then trace Aborted to Idle via `clear`.

> "Every machine runs the same PackML state machine, aligned to ISA-TR88: seven states, eleven transitions, each with a description tied to the standard. We built one master, replicated it across the line, then customized each copy. Notice there's only one way out of Aborted: an explicit clear."

### Scene 4: How it was built (~60s)
**On screen:** have the agent chat staged with a notebook link ready. Click the link and have the notebook come up. Open the full log, then sort by decisions and sort by notes (the decision log shows the line plan, PackML vs. SEMI E10/E58, naming conventions). Highlight that multiple agents contributed to creating the model: Claude to build the model, ChatGPT for compatible graphics. Point out that even this script is in the notebook (NOTE-0010). Then cut to a Capella Fabric read and patch.

> "None of this was ad hoc. An engineering notebook captured every decision as it happened: why PackML over E10, how exchange items are named, even the mistakes we hit and fixed. More than one agent worked on this model: Claude built the model, and ChatGPT produced compatible graphics. Even this script is in the notebook. Capella Fabric let the AI read the model and write changes back to it, like naming 67 elements in one pass and allocating exchange items. The engineer made the calls. The tools kept the model and the record consistent."

### Scene 5: Pivot to the AI agent (~90s)
**On screen:** Simcenter AI agent chat with the Capella Fabric bundle connected.

> "Now the payoff. The model isn't just documentation. An agent can reason over it."

**Chat beat:** ask the agent, "Filling Station is reporting Aborted. What do I do?"

> "The agent reads the state's definition, traces what led there, and checks where `clear` is wired. It finds that only the Operator can issue it. It recommends: diagnose the fault, issue clear, then start. It also notes that Line Control suspends the machines downstream of the fault and unsuspends them once Filling Station recovers."

### Closing line
> "The agent doesn't restart the line. It tells a human exactly what the model says is required, and the model itself enforces that a person authorizes it."

### Check before recording
- **Fix `File Bottle`** (the Filling Station function). It is almost certainly meant to be `Fill Bottle`, and it will be visible in the Scene 2 function chain.
- **Scene 5 wording is generic.** The Simcenter agent's interface hasn't been seen in this repo, so adjust the narration to match what actually appears on screen.
- **Startup order.** If the agent should walk a full multi-station restart, confirm the sequence against the model before scripting it.
