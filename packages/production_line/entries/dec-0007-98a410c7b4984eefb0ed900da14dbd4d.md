## Decision: qualify ExchangeItem names by machine, leave State names alone

**Status:** Active

After disconnecting the first 2 RPL replicas (Infeed Load, Filling Station) from the REC, each machine now has its own fully independent copy of the 7 states and 9-10 exchange items — confirmed via capella-fabric (different UUIDs across the board, no shared references).

Two different naming problems came up, and they got two different answers:

**State names — left unprefixed.** Initially considered prefixing every state (e.g. `Filling_Idle`) to fix confusion when browsing a flat list of all states across all machines. Decided against it: a state machine diagram is already scoped to one component, so there's no ambiguity within any single diagram, and prefixing would break the exact TR88.00.02 vocabulary match (NOTE-0002) that lets the model be audited against the standard at a glance. If per-machine disambiguation is needed outside a diagram (Explorer tree, tabs), the fix is to rename the generic `StateMachine 1` object itself, not the states inside it — not yet applied.

**ExchangeItem names — qualified with `<Component>.<event>`.** This was a different, concrete problem: allocating exchange items onto a functional exchange in Capella uses a flat, unscoped picker with no diagram context — every machine's identically-named `start`/`stop`/`hold`/etc. shows up side by side with no way to tell them apart until clicked. Since there's no containing-diagram context to rely on here (unlike states), the name itself has to carry the disambiguation. Applied `<Component>.<event>` naming (capella-fabric commit d2f56404, pushed to master) to all 30 exchange items across Master, Infeed Load, and Filling Station — e.g. `InfeedLoad.start`, `FillingStation.stop`.

**Trade-off noted:** since state transitions display their trigger's name, transition arrows on the diagram will now show the qualified name (e.g. `InfeedLoad.start`) — only the state boxes stay clean.

**Reference:** NOTE-0002 (PackML/TR88 state model), NOTE-0005 (port/exchange naming best practice — same principle, extended here to distinguish diagram-scoped elements from flat-list-selected ones).
