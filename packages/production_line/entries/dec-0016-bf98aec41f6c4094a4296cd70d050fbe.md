## Control Machines: line-suspend logic added (suspend all other machines when any machine is Stopped, Aborted or Held)

**Status:** Active. Supersedes the `Control Machines` wording in DEC-0015 (itself rebuilt from NOTE-0007).

Tony Komar directed that the `Control Machines` description (Line Control's function, uuid 794c5d6f) state the logic for suspending the line: when any other machine is stopped, aborted or held. Applied in capella-fabric commit 2a963e3e, pushed to master. `verify_model` on LA reported no issues, and the element was read back after the patch.

### Why
The Scene 5 dry run (OBS-0007) found that the earlier text said Line Control suspends the *downstream* machines "so in-flight material does not back up". That did not hold up: after a Filling abort, the stations upstream are the ones that back up, and downstream stations are starved. Tony's direction replaces "downstream" with the whole line.

### New description
> Line Control's supervisory function. Monitors the reports every machine sends on Machine Status (abort and machine-state-complete).
>
> Line-suspend logic: when any machine is Stopped, Aborted or Held, this function sends suspend to all the other machines, so the rest of the line pauses instead of continuing to run while one machine is not producing. It sends unsuspend to the other machines once no machine is Stopped, Aborted or Held.
>
> It never issues clear, reset or unhold. Recovery of the affected machine needs the Operator: clear from Aborted, reset from Stopped, unhold from Held.

### What was Tony's direction and what was mine
- **Tony's:** suspend the line (all other machines) when any machine is Stopped, Aborted or Held.
- **Mine, to be confirmed:** the unsuspend rule ("once no machine is Stopped, Aborted or Held") and the closing sentence about who issues clear, reset and unhold. Neither was dictated. The unsuspend rule follows from the suspend rule, but it is an inference.

### Gaps between this description and the model's structure (not changed)
1. **Line Control cannot see Stopped or Held.** Machine Status carries only `abort` and `machineStateComplete`. Stop and hold are Operator commands, and nothing reports them to Line Control. Only the Aborted case is wired. Making the description true for all three needs new exchange items on Machine Status. Creating exchange items is possible by patch, but allocating them to the exchanges is a separate step, so it was left alone.
2. **Unsuspend has no modeled trigger.** For the same reason, Line Control gets no signal that a machine has left Stopped, Aborted or Held.
3. **Suspend only applies to machines in Execute.** In every station's state machine the `suspend` transition runs only from Execute. A machine in Idle, Complete or Stopped has no suspend transition. The description says "all the other machines" and does not say this.
4. **Scene 5 narration still says "downstream".** NOTE-0010 was not changed in this step.
