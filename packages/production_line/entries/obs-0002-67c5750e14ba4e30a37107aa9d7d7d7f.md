## Tooling constraint: state machine creation vs. reading in the Capella model

The user has stated that current tooling does not support **creating** Capella state machines, but does support **reading** them. Note: the Handbook's `mcp_tools` package (capella-fabric's documented patch limitations) does not explicitly list state machines among the known `apply_model_patch` restrictions (it covers exchanges/physical links, child physical functions, and cardinality) — so this may be a limitation specific to the user's own workflow/tooling rather than a documented capella-fabric restriction. Treating it as authoritative for this repo either way.

**Practical implication for this project:** the PackML state machine (see accompanying note) will need to be **created manually in the Capella desktop editor** rather than via an agent patch. Once created, it can be read back, browsed, and referenced through capella-fabric as normal.
