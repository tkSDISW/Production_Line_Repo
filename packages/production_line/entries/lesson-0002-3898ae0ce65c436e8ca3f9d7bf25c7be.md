## Port names dropped by a Capella merge, then fully reapplied

While pulling model updates, the descriptive port names set on `Manage States` (Operator Commands In, Line Control In, Machine Status Out) had reverted to Capella's generic auto-generated labels (FIP 1, FIP 2, FOP 1) — user attributed this to a merge performed while integrating other changes. A stray empty duplicate `Manage States` LogicalFunction (no ports, not allocated to anything) also appeared in the same window, but resolved itself without intervention by the next pull.

**Fix applied (capella-fabric commits 905a1763, 6134a387, pushed to master):**
- Reapplied the 3 `Manage States` port names
- While verifying, discovered the 3 `Control Machine` port renames from the original naming table (NOTE-0005) had actually never been applied in the first place (proposed but not patched) — applied those too: Operator Commands Out, Machine Status In, Line Control Out

All 6 function ports plus the component-level exchanges/ports now fully match the naming scheme documented in NOTE-0005.

**Lesson:** property-only renames (not structural additions/deletions) can be silently dropped by a Capella/Git merge if the merge tool doesn't treat them as conflicting with concurrent changes to the same element. Worth spot-checking naming after any merge, not just after a plain pull.
