## Machine Status exchange items added: stopped, held, returnedToIdle (5 machines, 15 items)

**Status:** Active. Follows DEC-0016 and closes gaps 1 and 2 listed there, in part.

Tony Komar directed that the status exchange items discussed after DEC-0016 be added to each machine's functional exchange from `Manage States` into `Control Machines`, so Line Control has modeled inputs for the line-suspend logic.

### What was done (capella-fabric, pushed to master)
- **Step 1, commit 51e499b8:** created 15 ExchangeItems in the LA `Data` package, three per machine, named `<Machine>.<event>` per DEC-0007: `stopped`, `held`, `returnedToIdle` for InfeedLoad, FillingStation, CappingStation, LabelingStation and CasePackingStation. Each carries a description.
- **Step 2, commit e57022ca:** allocated the three items onto each machine's Machine Status functional exchange, using the technique in NOTE-0009. The exchanges are `Machine Status` (Infeed Load, unprefixed) and `<Station>.MachineStatus` for the other four.
- **Checked:** `verify_model` on LA reported no issues. Reading the model back showed each of the five exchanges now carries five items: abort, machineStateComplete, stopped, held, returnedToIdle.

### Naming and wording choices (mine, to be confirmed)
- **Event names:** `stopped`, `held` and `returnedToIdle` are my choice. The earlier proposal named the events but not the identifiers. They follow the camelCase style of `machineStateComplete`.
- **Not TR88 signals:** unlike the other exchange items, these are not from ANSI/ISA-TR88.00.02. Each description says so. They are model additions for the line-suspend logic.

### Remaining gaps
1. **Held has no exit notification.** `returnedToIdle` covers Stopped (after reset) and Aborted (after clear). Held exits to Execute, not Idle, so the unsuspend condition "no machine Stopped, Aborted or Held" cannot be detected for Held. It needs another item, for example `resumedExecute`, or `returnedToIdle` could be reworded. Not added.
2. **Component exchange roll-up not read back.** NOTE-0009 records that allocation onto a functional exchange rolls up to its component exchange (`<Station>.LineControlInterface`). That was not read back this time.
3. **Direction on Infeed Load.** Infeed Load's Line Control component exchange runs Line Control to station, the opposite of the other four (noted earlier). Machine Status notifications flow station to Line Control, so that roll-up may look odd there.
4. **State machines do not emit these.** No transition or state in any state machine references the new items. They exist on the exchange only. The demo can show them as allocated. They are not triggers.
5. **`Control Machines` description** still says "Stopped, Aborted or Held" without saying Held's exit is unreported (see 1).
6. **Scene 5 narration** in NOTE-0010 still says "downstream".
